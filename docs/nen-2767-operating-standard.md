# RoofSignal NEN 2767 Operating Standard

Status: internal operating baseline.

## Principle

RoofSignal should work NEN 2767-aligned from day one.

NEN 2767 is the Dutch reference method for objective and uniform condition assessment of building and infrastructure elements. RoofSignal should use its core logic in operations, data capture and reporting: defects are assessed per building element using seriousness, extent and intensity, leading to a comparable condition view and maintenance priority.

Do not claim a full certified NEN 2767 condition measurement unless the assignment scope, inspector competence, evidence depth, object coverage and liability position support that claim.

Commercial wording:

- Use: NEN 2767-aligned condition thinking.
- Use: condition scores and defect classification based on NEN 2767 principles.
- Use: suitable as structured input for MJOP and maintenance prioritisation.
- Avoid by default: certified NEN 2767 inspection.
- Avoid by default: complete replacement for MJOP, structural assessment or specialist destructive investigation.

## Operational Standard

Every RoofSignal assessment should capture observations in a structure that can support NEN 2767-style reporting later.

Minimum fields per finding:

- Object ID.
- Building or section.
- Building element.
- Element location.
- Material or system.
- Defect category.
- Defect description.
- Seriousness.
- Extent.
- Intensity.
- Indicative condition score.
- Risk type.
- Priority.
- Recommended action.
- Recommended term.
- Evidence image IDs.
- Confidence.
- Limitation or assumption.
- Inspector/reviewer.
- Review status.

## Scoring Discipline

Use a 1-6 condition scale internally:

- 1: very good.
- 2: good.
- 3: reasonable.
- 4: moderate.
- 5: poor.
- 6: very poor.

The score must be explainable from the observed defect, not guessed from visual impression alone.

Each finding should answer:

1. What building element is affected?
2. What defect is visible?
3. How serious is the defect for function, safety, watertightness or maintenance?
4. How much of the element is affected?
5. How developed is the defect?
6. What should the customer do next?

## Field Workflow

Before inspection:

- Define object scope and excluded elements.
- Determine whether the assignment is a quickscan, object report, portfolio scan or explicit NEN 2767 condition measurement.
- Prepare a building element checklist.
- Define minimum evidence requirements per element.

During inspection:

- Capture overview images before detail images.
- Capture every relevant building element, including elements without visible defects when needed for baseline comparison.
- Photograph defects from context and detail perspective.
- Record uncertainty immediately instead of fixing it later from memory.
- Capture enough evidence to support seriousness, extent and intensity.

After inspection:

- Convert every material finding into structured data.
- Separate observation, interpretation and recommendation.
- Assign seriousness, extent and intensity.
- Assign indicative condition score and priority.
- Review high-priority findings before delivery.
- Flag items that require specialist follow-up instead of stretching the claim.

## Report Standard

Reports should show:

- Scope and limitations.
- Method and evidence basis.
- Condition overview per building element.
- Findings with seriousness, extent, intensity and condition indication.
- Priority list.
- Recommended actions and term.
- MJOP input where relevant.
- Evidence images and annotations.

The report should remain decision-oriented. NEN 2767 provides the structure; RoofSignal still sells maintenance insight, not a bureaucratic form.

## Data Standard

Nothing may live only in a PDF.

NEN 2767-aligned fields must be stored as structured data so RoofSignal can later compare:

- Buildings.
- Portfolios.
- Reinspection history.
- Element condition trends.
- Defect recurrence.
- Contractor follow-up.
- Budget impact.

This is a strategic advantage: competitors can say they follow the norm; RoofSignal should turn the norm into a reusable intelligence layer.

## Quality Control

Before delivery, check:

- Does every P1/P2 finding have evidence?
- Does every condition score have a reason?
- Are assumptions and inaccessible parts named?
- Are serious defects reviewed by a second person when possible?
- Does the report avoid unsupported certainty?
- Does the report avoid underplaying visible risk?
- Is the output useful for a maintenance decision?

## Training Path

Short term:

- Use NEN 2767 terminology and structure internally.
- Build checklists and report templates around the method.
- Collect examples per defect type.

Medium term:

- Complete formal NEN 2767 training.
- Build an internal defect library.
- Add reviewer calibration sessions.

Long term:

- Offer explicit NEN 2767 condition measurements as a defined product tier.
- Support MJOP workflows with structured exports.
- Use historical condition data for portfolio intelligence.

## Source

Reference: NEN describes NEN 2767 as the objective and uniform method for measuring physical quality of building and installation elements, using seriousness, extent and intensity of defects to support condition scoring, classification and maintenance prioritisation.
